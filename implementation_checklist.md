# Проверка выпуска

Автоматические проверки перечислены в `docs/AUDIT_REMEDIATION.md`. Этот список — действия для приёмки на Debian, а не заявление, что они уже выполнены на вашем сервере.

- [ ] `go test ./...`, `go test -race ./...`, `go vet ./...`, сборка `CGO_ENABLED=0`.
- [ ] Unit запущен от homeshare, config 0600, security.log 0600, data 0750/0640.
- [ ] `ss -ltnp`: только loopback:8090; снаружи только Caddy:80/443.
- [ ] DuckDNS A/AAAA корректны; внешний сертификат Let's Encrypt; локальный CA доверен на устройствах.
- [ ] SSH доступ сохранён после правил UFW.
- [ ] CLI create показывает QR; без TOTP вход отклонён; CLI reset-totp/delete отзывают сессии; unlock снимает блокировки.
- [ ] Админ создаёт Person и invite; QR/код показан один раз; повторная активация одноразового кода запрещена.
- [ ] Пользователь загружает, прерывает и возобновляет файл, отменяет загрузку; потеря localStorage объясняет ожидание TTL.
- [ ] Файл меньше declared разрешён; больше declared/32 МиБ chunk отклонён; квоты и диск не обходятся альтернативным API.
- [ ] Скачивание Range, preview, ZIP Store, отмена скачивания; в traffic учтены реальные байты и allowance.
- [ ] Подозрительный файл в карантине; чужой Person не видит; approve публикует, protected запрещает пользовательское удаление.
- [ ] Действия админки: квоты, expiry/forever, sessions, uploads, traffic, блокировки, поиск/сортировка/страницы, audit.
- [ ] Runtime настройки переживают restart. Дневной backup не дублируется; пробное восстановление БД и data на отдельной копии.
- [ ] Disable сохраняет файлы, delete по умолчанию сохраняет orphaned; отдельный флаг удаляет байты.
- [ ] `fail2ban-regex` совпадает с IPv4/IPv6 событиями; `fail2ban-client -t` и jail работают.
- [ ] Отдельно проверить длительный большой upload/download за реальным Caddy и переполнение диска на тестовом filesystem.
